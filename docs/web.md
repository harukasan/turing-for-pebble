# Web core and demo

The Web implementation has two layers. `src/core/` exports `TuringPlayer` and its settings types through `src/core/index.ts`. It owns the Canvas rendering loop, the shared C core loaded as WebAssembly, the Float32 reference mode, clock drawing, seeding, and simulation lifecycle. It has no React, Panda CSS, download, or page-content dependency. The lower-level adapters remain in `lib/` because the numerical tests and build scripts use them directly. `lib/palettes.ts` lists the display palettes, their ids, names, and stops, with the integer color mapping of the core, and the demo's palette selector is built from it.

`src/demo/` is the standalone React page. It owns the controls, explanatory text, browser-only tool registration, settings and Pebble header serialization, and PNG, JSON, and header downloads. `src/demo/main.ts` mounts it in `index.html`. The demo's `useDemo` hook translates React state into calls on `TuringPlayer`. Removing the demo does not remove the player API.

The core can be used from another browser page without mounting the demo. For a source-bundled, preview-only integration in another site, see [Embed only the preview](embed-preview.md).

```ts
import {
  TuringPlayer,
  defaultParameters,
  defaultPlayerSettings,
} from "./src/core";

const canvas = document.querySelector("canvas")!;
const player = new TuringPlayer(
  canvas,
  "/pebble-turing/",
  defaultPlayerSettings,
  {
    onStats(stats) {
      console.log(stats.steps);
    },
    onLoading(loading) {
      console.log(loading);
    },
    onError(error) {
      console.error(error);
    },
  }
);

await player.load("q15-120", 42);
player.play();
player.setParameters({ ...defaultParameters, feed: 0.035 });
player.pause();
player.advance(100);
player.seed(0.5, 0.5);
player.dispose();
```

`seed(x, y)` accepts normalized Canvas coordinates in `[0, 1)`. `setSettings()` changes simulation and rendering settings without resetting the field. `load(engine, seed)` resets the field. The caller must call `dispose()` when removing the view. The asset base must contain `wasm/rd.wasm` and `fonts/clock-fonts.json`.

`src/settings/` is the watch settings page, a third layer without React or Panda CSS. `settings.ts` holds the settings codec shared with the tests: the fourteen settings in the order of the message keys, their ranges and `config.h` defaults, and the query string and JSON forms. `preview.ts` runs the watch's field with `WasmSimulation`, `buildMask`, and `drawClock` from `lib/`, and `main.ts` builds the controls from the presets, the palettes, and the coefficient bounds that `src/core/modes.ts` shares with the demo. `vite.settings.config.ts` builds the page with the Wasm core and the clock glyphs inlined as `data:` URLs, and `scripts/embed-config.mjs` inlines its script and style into `build/config/index.html` and embeds that page in the phone script. `pnpm run dev:settings` serves the page for development. Without embedded settings it reads them from the query string, for example `?feed=950&kill=1868&da=32768&db=16384&dt=32768&palette=0&low=7698&high=13827925&font=0&avoid=1&clock=1`, and otherwise shows the defaults.

The standalone demo runs `panda codegen` from `panda.config.ts`, then Vite. The ignored `styled-system/` directory is regenerated by `pnpm run typecheck` or `pnpm run build`. To test the demo under a subpath, run `TURING_BASE_URL=/pebble-turing/ pnpm run build` and serve `dist/` at that path. The standalone demo remains local only.
