# Web core and demo

The Web implementation has two layers. `src/core/` exports `TuringPlayer` and its settings types through `src/core/index.ts`. It owns the Canvas rendering loop, the shared C core loaded as WebAssembly, the Float32 reference mode, clock drawing, seeding, and simulation lifecycle. It has no React, Panda CSS, download, or page-content dependency. The lower-level adapters remain in `lib/` because the numerical tests and build scripts use them directly.

`src/demo/` is the standalone React page. It owns the controls, explanatory text, browser-only tool registration, settings and Pebble header serialization, and PNG, JSON, and header downloads. `src/demo/main.ts` mounts it in `index.html`. The demo's `useDemo` hook translates React state into calls on `TuringPlayer`. Removing the demo does not remove the player API.

The core can be used from another browser page without mounting the demo:

```ts
import {
  TuringPlayer,
  defaultParameters,
  defaultPlayerSettings,
} from "./src/core";

const canvas = document.querySelector("canvas")!;
const player = new TuringPlayer(
  canvas,
  "/pebble-turing/",
  defaultPlayerSettings,
  {
    onStats(stats) {
      console.log(stats.steps);
    },
    onLoading(loading) {
      console.log(loading);
    },
    onError(error) {
      console.error(error);
    },
  }
);

await player.load("q15-120", 42);
player.play();
player.setParameters({ ...defaultParameters, feed: 0.035 });
player.pause();
player.advance(100);
player.seed(0.5, 0.5);
player.dispose();
```

`seed(x, y)` accepts normalized Canvas coordinates in `[0, 1)`. `setSettings()` changes simulation and rendering settings without resetting the field. `load(engine, seed)` resets the field. The caller must call `dispose()` when removing the view. The asset base must contain `wasm/rd.wasm` and `fonts/clock-fonts.json`.

The standalone demo runs `panda codegen` from `panda.config.ts`, then Vite. The Panda configuration and Web formatting rules match harukasan-dev. The ignored `styled-system/` directory is regenerated by `pnpm run typecheck` or `pnpm run build`. To test the demo under a subpath, run `TURING_BASE_URL=/pebble-turing/ pnpm run build` and serve `dist/` at that path.

The intended harukasan.dev integration keeps this repository separate and consumes a versioned build of the core. That artifact build and the HonoX route have not been implemented yet. The standalone demo remains local only.
