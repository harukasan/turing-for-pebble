# Web core and demo

The Web implementation has two layers. `src/core/` exports `TuringPlayer` and its settings types through `src/core/index.ts`. It owns the Canvas rendering loop, the shared C core loaded as WebAssembly, the Float32 reference mode, clock drawing, seeding, and simulation lifecycle. It has no React, Panda CSS, download, or page-content dependency. The lower-level adapters remain in `lib/` because the numerical tests and build scripts use them directly.

`src/demo/` is the standalone React page. It owns the controls, explanatory text, browser-only tool registration, settings and Pebble header serialization, and PNG, JSON, and header downloads. `src/demo/main.ts` mounts it in `index.html`. The demo's `useDemo` hook translates React state into calls on `TuringPlayer`. Removing the demo does not remove the player API.

The core can be used from another browser page without mounting the demo. For a source-bundled, preview-only integration in another site, see [Embed only the preview](embed-preview.md).

```ts
import {
  TuringPlayer,
  defaultParameters,
  defaultPlayerSettings,
} from "./src/core";

const canvas = document.querySelector("canvas")!;
const player = new TuringPlayer(
  canvas,
  "/pebble-turing/",
  defaultPlayerSettings,
  {
    onStats(stats) {
      console.log(stats.steps);
    },
    onLoading(loading) {
      console.log(loading);
    },
    onError(error) {
      console.error(error);
    },
  }
);

await player.load("q15-120", 42);
player.play();
player.setParameters({ ...defaultParameters, feed: 0.035 });
player.pause();
player.advance(100);
player.seed(0.5, 0.5);
player.dispose();
```

`seed(x, y)` accepts normalized Canvas coordinates in `[0, 1)`. `setSettings()` changes simulation and rendering settings without resetting the field. `load(engine, seed)` resets the field. The caller must call `dispose()` when removing the view. The asset base must contain `wasm/rd.wasm` and `fonts/clock-fonts.json`.

The standalone demo runs `panda codegen` from `panda.config.ts`, then Vite. The ignored `styled-system/` directory is regenerated by `pnpm run typecheck` or `pnpm run build`. To test the demo under a subpath, run `TURING_BASE_URL=/pebble-turing/ pnpm run build` and serve `dist/` at that path.

## GitHub Pages

`.github/workflows/pages.yml` publishes the standalone demo to <https://harukasan.github.io/turing-for-pebble/> on every push to `main` and on manual runs. The build job installs the pinned pnpm from `package.json` and Node 24.19.0 from `mise.toml`, then runs `pnpm install --frozen-lockfile` and `pnpm run build` with `TURING_BASE_URL` set to the Pages base path, and the deploy job publishes `dist/`. The workflow does not run Emscripten. It serves the committed `public/wasm/rd.wasm`, so rebuild and commit that file with any core change before it reaches `main`.

The repository's Pages source must be set to GitHub Actions under Settings, Pages, Build and deployment. The default `github-pages` environment accepts deployments only from `main`, so a manual run on another branch builds but does not deploy. To check the published layout locally, run `TURING_BASE_URL=/turing-for-pebble/ pnpm run build`, then `TURING_BASE_URL=/turing-for-pebble/ pnpm start` and open `http://localhost:4173/turing-for-pebble/`.
