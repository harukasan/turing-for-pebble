# Web and watchface behavior

## Web controls

The default implementation is the watch build, Q15 16-bit storage at 120 × 136, shown with interpolation. The implementation selector also offers Float32 at 120 × 136, Q15 at 100 × 114, 200 × 228 with one packed 16-bit word per cell (A as a 7-bit linear code and B as a 9-bit square-root companded code, written with dithered error diffusion), Float32 at 200 × 228, and Float32 at 100 × 114. The same-resolution pairs isolate numerical and storage differences from grid resolution. Switching implementations frees the old Wasm allocation when applicable and initializes the selected mode with the same seed. Changing the seed or preset also resets the field. Switching does not retain or synchronize elapsed steps, so compare the same seed, parameters, and displayed step count. The coefficient and timestep controls apply to the current field on the next step.

The モデル selector switches between Gray–Scott and FitzHugh–Nagumo. A model change resets the field with the model's default parameters (its first preset below), and only the presets and sliders of the current model are shown. FitzHugh–Nagumo runs in the Q15 modes and in Float32, so the packed 200 × 228 implementation is disabled while it is selected, and selecting the model there falls back to the watch build, Q15 at 120 × 136. The FitzHugh–Nagumo sliders are du, dv, ru, rv, av, k, dt, and rest, and 初期条件 selects init (円板から育てる, disks, or 断ち切った波面, the broken wave). Changing rest, av, or init resets the field once the slider rests, because they shape the initial field (u = rest and v = rest / av, with disks or the broken wave).

The Gray–Scott presets and the two stationary FitzHugh–Nagumo presets settle, and the spiral keeps turning.

Every Gray–Scott preset uses da 1, db 0.5, and dt 1, and every FitzHugh–Nagumo preset dt 1. The FitzHugh–Nagumo presets start from init 0 (disks of u = rest + 0.5) except `fhn-spiral`, which starts from the broken wave. [Shared C core](core.md#parameter-search) records how they were chosen. [The Gray–Scott comparison image](../public/reports/comparison.png) and [the FitzHugh–Nagumo one](../public/reports/fhn.png) show the presets after 10,000 steps.

The Float32 options run the original `Simulation.step` implementation for Gray–Scott and `FhnSimulation.step` (`lib/fhn-simulation.ts`, the same Laplacian and Euler step) for FitzHugh–Nagumo. Their initial 24 disks are placed using the C core's display-coordinate LCG, periodic distance, and radius range. The Q15 mode has exactly the same initial Gray–Scott concentrations, and FitzHugh–Nagumo values within the Q13 rounding of rest and rest / av, with the same seeded cells and the same broken wave. The packed mode starts from A = 64/127 instead of 0.5, while its B = 0.25 is exact. Interactive seeds also use display coordinates. Float32 computes with JavaScript number intermediates and stores each field in `Float32Array`. Its result is a reference for visual comparison, not a numerically identical Pebble build.

計算セルの間を補間 switches between interpolated rendering (`RD_ROW_BILINEAR`) and showing the cell under each pixel. The Float32 engines interpolate their float B, or u, at the same positions.

文字盤 selects the digital or the analog clock face (the face setting on the watch, below). 現在時刻 shows the current time. Turning it off starts from the current minute and shows a slider over the minutes of the day (0 to 1439, labeled HH:MM) that sets the time drawn and masked by either face on today's date, so the analog hands can be scrubbed to any position. The slider is a preview control and is not recorded in the settings JSON or `config.h`, while the face is.

Pause, speed, 100-step advance, pointer seeding, palettes, display scaling, PNG, and JSON controls remain. Wasm and clock-font loading failures produce a visible error and stop simulation. Selecting Float32 is explicit, never a silent fallback. Wasm linear memory is fixed and the rendering arrays are reused. The Float32 renderer writes into the same reusable `ImageData`.

The JSON output records the model, requested and effective parameters, implementation, storage, rounding, the initial condition, seed, version (5), dimensions, palette, and step count. In the Q15 modes the effective diffusion coefficients are the folded values the core computes with, `round(D × 32768 / 20) × 20 / 32768`, and the FitzHugh–Nagumo k and rest are the Q13 values `floor((round(x × 32768) + 2) / 4) × 4 / 32768`. Float32 records its requested parameters as effective because Q15 conversion is not applied. It is a settings record, not a state snapshot. Parameter history and hand-painted seeds are not serialized. `config.h` output is enabled for Wasm modes. It writes the watch's build header with the mode, seed, and rendering, and the effective parameters, palette, clock font, avoidance, and clock as the `RD_DEFAULT_*` settings the face shows until the phone sends its own. On-watch RGB2 output is always quantized, even if the Web's smooth-color preview option is enabled. The watch's own settings page is described under [Watch settings](#watch-settings).

The **細線** preset uses Feed 0.023 and Kill 0.052. With seed 42 at 10,000 steps, the 200 × 228 packed mode develops narrow curved bands. The 100 × 114 Q15 mode retains the structure with visibly wider bands. [The comparison image](../public/reports/thin-lines.png) shows these two outputs side by side at native display size, high resolution on the left. This is a deliberately difficult case for a coarse grid, not a guarantee of the same geometry across implementations.

## Clock

Two font sets are available, selected by the font setting on the watch, or fixed by `RD_BUILD_FONT`, and by the 時計フォント control on the Web:

| Set    | Time                    | Date                        |
| ------ | ----------------------- | --------------------------- |
| LECO   | LECO_42_NUMBERS at y=78 | LECO_20_BOLD_NUMBERS, y=128 |
| Bitham | BITHAM_42_BOLD at y=79  | BITHAM_30_BLACK at y=122    |

Without the date, the time line moves down so that the ink of the time glyphs is centered on the display, to y=86 for LECO and y=87 for Bitham. Bitham has no small font with digits, so its date uses BITHAM_30_BLACK. The Bitham tops center the digit 0 on the LECO digit centers. Lines are horizontally centered. The Web draws extracted 1-bit glyphs without antialiasing. The watch draws the glyphs itself into the framebuffer from the core's copy of the system font glyphs (`cm_draw`), which gives the same pixels as `graphics_draw_text` and is faster. It falls back to the system fonts only when the framebuffer cannot be captured, and the analog face then draws its hands as system lines of about the same width. White glyphs are drawn directly over the pattern without a background panel.

With digit avoidance (the avoidance setting on the watch, on by default and unavailable in mode 0, which is built without the mask area, and 数字を避ける on the Web, on by default for every engine), B is held at 0 in the grid cells under the digits, widened by a 1-pixel halo (`RD_HALO`), and the kill rate rises to 0.075 over the 5 cells around them. FitzHugh–Nagumo holds u at rest there instead and pulls u toward rest with a rate rising to 0.125 over the same 5 cells, which also keeps spiral waves from entering the digits. The pattern fades out a few cells before the digits without a band along their outline, and the masked cells show the background color. The mask is rebuilt from the same time as the drawn text at startup and at every minute change. Each minute change then raises the pending steps to 300 (`RD_MINUTE_STEPS_AVOID`) so the strokes freed by the previous digits refill. Mode 0 keeps 16 steps per minute and no mask, because a 300-step burst would take about 24 s there.

## Watch settings

The Pebble app's settings button opens a settings page for the watchface. The page and the watch share twenty-two integer settings, sent under the message keys of `pebble/package.json`:

| Setting          | Values                                                                                             | Default                                     |
| ---------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `MODEL`          | 0 Gray–Scott, 1 FitzHugh–Nagumo (modes 1 and 3 only)                                               | 0                                           |
| `P0` to `P9`     | The model's Q15 parameter vector as `rd_init_model` takes it, entries after the model's own 0      | 950, 1868, 22938, 11469, 32768, then zeros  |
| `PALETTE`        | 0 to 8 for the built-in palettes, 9 for the custom one                                             | 0, lime                                     |
| `LOW`, `HIGH`    | Dark and light stops of the custom palette, 0xRRGGBB                                               | The lime stops                              |
| `STOPS`          | Stops of the custom palette, 2 to 4                                                                | 2                                           |
| `MID1`, `MID2`   | Middle stops of the custom palette, 0xRRGGBB                                                       | A third and two thirds of lime              |
| `FONT`           | 0 LECO, 1 Bitham                                                                                   | 0                                           |
| `AVOID`, `CLOCK` | 0 or 1                                                                                             | 1                                           |
| `DATE`           | 0 or 1, the date line under the time                                                               | 1                                           |
| `FACE`           | 0 digital, 1 analog                                                                                | 0                                           |

For Gray–Scott the vector is feed, kill, Da, Db, and dt, each 0 to 32768. For FitzHugh–Nagumo it is Du, Dv, ru, rv, av, k, dt, rest, and init, with k and rest from −32768 to 32768, ru at most 8192, and init 0 or 1 ([Shared C core](core.md#fitzhughnagumo)). The watch and the phone check the vector with the model's ranges, the watch through `rd_check_params`, and a build folded to one model (`RD_BUILD_MODEL`) or a packed mode accepts only its own model. The page offers both models to every build and assumes the phone script and the watch come from the same default build, which runs both. A message with a model the build does not run is rejected whole, palette and clock included. The defaults are the `RD_DEFAULT_*` values of `pebble/src/c/config.h`, `RD_DEFAULT_MODEL` and `RD_DEFAULT_PARAMS` for the model and its vector. Da and Db default to Thin, which draws thinner stripes than the core's default of 1.0 and 0.5 and still covers the face within the startup. Below about 0.6 the coral preset leaves empty areas at the end of the startup. The Web demo keeps 1.0 and 0.5. Everything else, including the mode, the seed, the rendering, the startup length, the halo, and the minute steps, stays fixed at build time.

The page (`src/settings/`) offers the two models, and for each model its presets by name and Custom: for Gray–Scott the five presets with Feed and Kill sliders, and three stripe widths, Thick, Medium, and Thin (Da and Db of 1.0 and 0.5, 0.8 and 0.4, and 0.7 and 0.35), with Da, Db, and Dt sliders within the Web demo's ranges, and for FitzHugh–Nagumo the three presets with Du, Dv, ru, rv, av, k, Dt, and rest sliders and the initial condition, Disks or Cut wave. A Gray–Scott preset sets feed and kill and keeps the diffusion and the time step, a FitzHugh–Nagumo preset sets every parameter, and choosing a model starts from its first preset. The number beside each slider is a field that takes any value in the range the watch accepts, also outside the slider's range, and applies it when the entry is committed. The page also offers the nine built-in palettes with swatches of their quantized colors, a custom palette of 2, 3, or 4 colors, shown in one row from Dark to Light and joined by lines that blend from one color to the next, each picked from the watch's 64 colors under its own button, where middle colors already picked stay and a middle color that comes into use starts halfway between its neighbors, the clock face, Digital or Analog, the clock font, the clock switch, and the date and avoidance switches, which need the clock. In Japanese the avoidance switch is named by what the face shows, 数字を避ける for the digits and 針と日付を避ける or 針を避ける for the hands with or without the date, while the English Keep the pattern off the clock covers every face. A preview above the controls runs the shared core as WebAssembly in mode 3 with seed 42, the settings' model and parameters, the watch's mask of the digits or the hands, and quantized interpolated rendering for 1,650 steps, about the steps of the watch's startup, at twice the watch's pace so that it grows in 15 s, and draws the clock with the phone's time, the analog hands at the minute without a sweep. `PREVIEW_SPEED` in `src/settings/preview.ts` sets the pace. A change of the model, a parameter, the face, the font, or the clock runs the preview again after 300 ms, and a palette change only recolors it. The preview's field is the watch's field, which the tests check against the golden hashes of both models. That holds for the mode 3 production build. The mode 0 and 1 builds bundle the same page, so their preview still shows mode 3 with interpolation and digit avoidance, and the mode 0 watch rejects FitzHugh–Nagumo settings. Export and Import Settings, a section closed until its heading is tapped, exports the settings as `turing-settings.json`, a JSON file with a format name, a version (2, and version 1 files that name the Gray–Scott coefficients are still read), and the twenty-two settings, through the share sheet where the web view offers one and as a download in a browser. The Pebble app's web view offers neither and shows a downloaded file in place of the page, so inside the app, where the page is a `data:` URL, Export copies the file's text and shows it in a text field instead. A settings file, or its text pasted into that field, is imported after checking every value. An import only fills the page, and Save sends it. Save returns the settings as JSON through `pebblejs://close#`, or through the `return_to` address that `pebble emu-app-config` adds, and Cancel closes the page without them.

The page is embedded in the phone script. The phone opens it as a `data:` URL of about 80 KB with the stored settings in it, so it needs no hosting and works offline. A build with `RD_BUILD_CONFIG_URL` opens that address instead, with the settings in the query string. The phone script stores the settings the page returns, sends them to the watch, and sends its stored copy again when the face starts, for example after a reinstall. It sends only settings whose every value is in range, the vector by its model's ranges, and it converts a copy stored before the model, which named the Gray–Scott coefficients, to model 0 and its vector.

The page is in English and Japanese, with a switch at its top. The labels above are the English ones. In Japanese the presets carry the Web demo's names. The page starts in the language that the phone script embeds or that a hosted page gets as `lang` in its query string, and otherwise in Japanese when the web view's language starts with `ja` and in English for any other. The saved JSON carries the language as `lang` beside the settings. The phone script keeps it apart from the settings and embeds it the next time, alone if no settings are stored, and it never goes to the watch. The strings are in `src/settings/i18n.ts`, and the tests check that both languages have the same ones.

The watch applies a message only if every value it carries is in range. It stores the settings as one versioned persist blob (version 5 since the model and the vector, after version 4 added the clock face) and reads the blob back at launch with the same checks, falling back to the defaults. A new model or new parameters restart the field from the seed with `rd_init_model` and run the 30 s startup again. Showing or hiding the date with avoidance on restarts the field too, because it moves the time and changes the mask. Removing the digit mask, by turning the clock or avoidance off, restarts the field the same way, because the empty area under the former digits would take hours to fill at the minute steps without avoidance. A new font or a new mask refills like a minute change with 300 pending steps, and a palette change only redraws. A build with `RD_BUILD_FONT` compiles one font set and ignores the font setting, and mode 0 ignores avoidance. A build with `RD_BUILD_LOG=1` logs the settings as four `RD settings` lines, the model and the vector first, with their source: d for the defaults, p for the stored blob, and m for a message.

The analog face (the face setting on the watch, アナログ on the Web, and fixed by `RD_BUILD_FACE=1` in `mode-3-analog`) draws an hour hand, a minute hand, a center disk, and the date line of the selected font set. Angles are in units of 1/1440 of a turn (0.25°) clockwise from 12 o'clock: the minute hand is at `minute × 24` and the hour hand at `(hour mod 12) × 120 + minute × 2`, so a minute moves them by 24 and 2 units. The dial center is display pixel (100, 104). The minute hand is 80 pixels long with a radius of 2, the hour hand 54 pixels with a radius of 3, both with round tips, and the center disk has a radius of 5. Together they stay within columns 18 to 182 and rows 22 to 186. The date line is centered as in the digital face, with its text box at y=204 for LECO (digit rows 210 to 223) and y=192 for Bitham (digit rows 201 to 221), below the reach of the hands. The pixels come from the core (`cm_build_analog`, [Shared C core](core.md)): the Web draws the 200 × 228 halo 0 bitmap, and the watch draws the same pixels into the framebuffer through `cm_draw_analog`. The hands and the date are white and drawn directly over the pattern like the digits. With avoidance (針と日付を避ける on the Web), the cells under the hands, the disk, and the date are masked with the same halo and kill ramp as the digits, so the pattern fades out around the hands. The masked rows then span the dial: in mode 3 the rows that read the mask levels average about 102 of 136 over the 720 times of a half day, against about 44 for the digits.

## Scheduling

Interactive Web mode renders up to 30 times per second. It checks elapsed compute time after each complete step and yields after approximately 8 ms. One complete step can exceed the budget. The Speed slider sets the steps attempted per frame within that budget, and the 100-step advance runs up to 8 steps per frame within it.

The Web no longer simulates the watch's startup, minute-work queue, or backlight scheduling. It remains an interactive comparison view. It does sweep the analog hands as the watch does: when the shown minute changes, by the clock or the time slider, the hands ease from their shown angles to the new ones over 1 s (`SWEEP_MS`) through the core's `cm_sweep_angle`, and the mask of either engine is rebuilt only in frames where an integer angle changed. The exported `config.h` retains the watch's scheduling constants, and settings JSON records the minute-step count.

The watch uses SDK BacklightService and AppFocusService. It does not subscribe to accelerometer data. Startup runs in timer slices for `RD_STARTUP_MS` (30 s) after launch or a settings change that restarts the field, or until `RD_STARTUP_STEPS_MAX` (2,500) steps, about 45 s at the measured rate, whichever comes first, which is about 1,650 steps in mode 3 on the physical Pebble Time 2. A minute change during the startup is covered by the startup steps, and only the steps it is still owed at the deadline run after it. The deadline is wall time since launch, so time spent unfocused during the startup counts against it. Minute updates rebuild the digit mask and raise the pending steps to 300 (16 more without avoidance). With the analog face a minute update that arrives while focused with the clock shown instead starts a sweep: over `RD_SWEEP_MS` (1 s) each slice first moves the hands to their eased angles (`cm_sweep_angle`, a quadratic ease-out along the shorter way round, so 11:59 to 12:00 passes through 1439 to 0), rebuilds the mask within the 30 ms slice budget whenever an integer angle changed, and then runs steps as usual. A minute moves the minute hand 24 units and the hour hand 2, so a sweep rebuilds the mask at most 26 times, and fewer in practice, because slices come about every 40 ms and the ease-out slows the last units. The count is logged per sweep ([Validation](validation.md)). The slices continue while the sweep runs even when no steps are pending, and a slice that moved the hands redraws under the same 50 ms throttle. The final slice snaps to the target angles. A focus loss snaps a running sweep to its target, a minute update while unfocused sets the new angles at once, and a new face or date setting shows the hands at the current time, so the drawn hands always equal the masked ones. While work is pending, each callback runs steps until a 30 ms budget is used, checked after every complete step (three steps of about 14 ms in mode 3), then reschedules itself 1 ms later. The layer is marked dirty once another slice would pass 50 ms since the last mark, which gives about 20 frames per second against the OS ceiling of about 27, and when the queue empties. Backlight animation runs the same 30 ms slices and 50 ms redraws for at most five seconds, and draws the last computed steps when the window ends. Focus loss cancels timers and ends a backlight window, and backlight-on is ignored while unfocused. Focus restoration resumes pending work. Backlight-off cancels animation while pending startup or minute work remains eligible for timer execution. A separate five-second timer bounds each backlight animation window. The field is blitted into the framebuffer as ARGB8 rows from `rd_row_rgb2` with `RD_RENDER_FLAGS` (interpolated in mode 3) within the unobstructed bounds, and the clock fonts are loaded at launch and when the font setting changes. A restart resets the startup accounting, so the `RD startup` lines describe the latest startup, while the minimum free heap and the clock fault flag cover the whole session.

Timing uses the public `time_ms` API. The emulator's wall-clock seconds and tick-derived millisecond component can be discontinuous. Negative or unexpectedly large deltas end the current slice and mark timing diagnostics invalid. Such values must not be interpreted as a valid benchmark or used to select a production mode. The watch measured the 30 ms slices and 50 ms frames of this pacing directly ([Validation](validation.md)). Production builds have no logs. A build with `RD_BUILD_LOG=1` (or `RD_BUILD_PROFILE=1`, `RD_BENCH`, or `RD_FRAME_BENCH`) logs `RD init` at launch, four `RD startup` lines when the startup and any refill it still owes have finished (validated wall time, steps per second times 10, the average step, field, and text times, the minimum free heap, and whether a focus loss or a gap of 5 s or more between slices interrupted the run or the clock invalidated it), an `RD mode` progress line every 256 steps (`RD prof` lines with `RD_BUILD_PROFILE=1`, which also runs a clock calibration loop), `RD light` with the steps and frames of each backlight window, and, with the analog face, `RD sweep` at the end of each sweep with its mask rebuilds, their longest time, its duration, and the steps run during it.

## Memory reporting

The Web UI shows one memory figure for the selected implementation: the total core allocation reported by the C core for the Wasm modes (fields, scratch rows, control data, the rendering rows and tables, alignment, and the digit mask levels), or the four JavaScript concentration arrays for Float32. The watch's clock mask bitmap is a separate allocation outside the core. Build sizes, compiler stack reports, and the physical measurement of the watch (startup, steps per second, minimum free heap) are in [Validation](validation.md) and `public/reports/comparison.json`. Runtime minimum free heap already includes allocations and must not be added to an estimate of remaining heap.

The acceptance thresholds are a 128 KiB app region and at least 16 KiB minimum free heap during normal operation. Compiler stack reports describe application functions. OS and library stack contributions are additional. Mode 3 is the watch build.
